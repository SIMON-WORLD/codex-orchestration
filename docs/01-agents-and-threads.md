# 01 · agent 式协作模型与线程层级

## 心智模型：一条会话 = 一个可指挥的“工作者”

Codex 是 **agent 式**的：你给目标，它自主拆解、用工具执行。很多任务其实可以**拆成多条独立会话并行**，由一条**主导会话**统一协调。

一条会话（thread）可以扮演两种角色：

- **主导者（coordinator / leader）**：拥有编排工具，负责建会话、派活、等结果、验收、合并。
- **工作者（worker）**：接收一个明确任务，干完把结果交回来。

> 主导者不一定亲自干活，它更像“项目经理”。这正是 `codex-orchestration` 的核心。

## 几个容易混淆的概念

| 概念 | 说明 |
|---|---|
| **thread / 会话 / 任务** | Codex 侧边栏里的一条独立对话。可独立创建、查看、归档、分享。 |
| **worktree** | 绑定到某个 git 仓库的会话工作区，通常用于“在某个项目里干活”，会生成独立的工作树。 |
| **subagent（子代理）** | 在**同一条会话内部**派出的并行助手，不显示在侧边栏。适合“当前任务内的并行分工”。 |
| **handoff（交接）** | 把一条会话（含其 git 状态）整体移交到本机、远程 host 或 worktree 继续。 |

**重要区分：**

- 想让任务**出现在侧边栏、成为独立会话** → 用 `create_thread`。
- 只想要**当前会话内的并行小弟** → 用 subagent 类机制（不产生侧边栏条目）。
- 要“把任务正式转交给另一个会话并持续跟进” → `handoff_thread` / `send_message_to_thread`。

## 一条会话能用到什么工具？

Codex 应用会给会话注入一组 `codex_app` 工具。**不同会话拿到的工具集可能不同**（见 `04-faq` 的“精简工具清单”一节）。理想情况下，一条 fully-enabled 的会话拥有完整 `codex_app` 工具集（见 `03-tool-reference.md`）。

完整工具集会随版本变化，因此本仓库把工具参考做成**由脚本生成**，便于随时刷新。

## 建议的起步流程

1. 先想清楚：这件事是**单线程做完**，还是**拆给多条会话并行**。
2. 如果需要并行：让主导会话用 `create_thread` 建 worker，用 `send_message_to_thread` 派活。
3. 用 `wait_threads` 等结果，`read_thread` 验收，合格就合并，不合格就打回。
4. 长期/高频的事，用 `automation_update` 设成定时。
